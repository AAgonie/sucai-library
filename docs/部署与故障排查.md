# 部署与故障排查手册

本手册说明如何把“短剧广告大图素材库展示网站”部署到一台 Windows 服务电脑，供局域网内已授权用户访问。示例中的 `FILE_SERVER`、`SERVICE_HOST` 与共享目录均为占位符，不能直接照抄为真实环境配置。

## 1. 部署前准备

- Windows 电脑一台，建议使用稳定的固定账号运行服务。
- Python 3.12，并能在终端执行 `python --version`。
- 如需重新构建前端，安装当前 LTS（Long-Term Support，长期支持）版本 Node.js。
- 服务账号已经被授予目标共享目录的读取权限；若要生成派生图，则还需要输出目录的写入权限。
- 将项目源代码复制到任意本地目录。不要把数据库、日志、实际配置、账号密码或素材文件打包进公开代码仓库。

## 2. 首次部署

### 2.1 安装基础依赖

在项目根目录执行：

```powershell
python -m pip install -r backend\requirements.txt
```

### 2.2 创建本地配置

复制模板：

```powershell
Copy-Item config.example.json config.local.json
```

编辑 `config.local.json`，填写本环境的数据源。Windows SMB（Server Message Block，Windows 文件共享协议）示例结构如下：

```json
{
  "nas": {
    "type": "smb",
    "base_path": "\\\\FILE_SERVER\\shared\\image-library",
    "username": "",
    "password": "",
    "recursive": false
  }
}
```

`host` 与 `share` 仅在 HTTP 数据源模式需要。SMB 模式优先使用 `base_path`。`config.local.json` 含可能的访问凭据，必须始终只保存在服务电脑，不能提交到 Git。

### 2.3 可选：安装 OCR

如果需要文字识别，按 [本地 OCR 安装与使用](ocr-local.md) 完成 PaddleOCR 安装。若暂不安装 OCR，浏览、扫描和筛选功能仍可使用。

### 2.4 构建前端（仅改动前端源码时需要）

发布包中若已包含 `frontend/dist`，可跳过此步骤。需要构建时执行：

```powershell
Set-Location frontend
npm ci
npm run build
Set-Location ..
```

### 2.5 启动与验收

- 本机使用：`start.cmd`
- 局域网服务机使用：`start-nas.cmd`

启动后，在服务电脑浏览器打开 `http://127.0.0.1:8000`。局域网客户端使用 `http://SERVICE_HOST:8000`，其中 `SERVICE_HOST` 是服务电脑的可达地址。

基础验收顺序：

1. 打开网站，确认首页可加载。
2. 点击连接测试，确认服务账号可读取数据源。
3. 扫描少量目录，确认缩略图和筛选可用。
4. 若启用 OCR，对一张图片执行识别并等待任务完成。
5. 使用另一台局域网电脑访问同一服务地址，确认能看到同一份数据库结果。

## 3. Windows 共享访问

服务进程使用的是启动它的 Windows 账号，不是浏览器当前用户。先在同一个服务终端验证：

```powershell
Get-ChildItem "\\FILE_SERVER\\shared\\image-library" -ErrorAction Stop | Select-Object -First 1
```

若命令失败，网站扫描也会失败。建议为共享访问使用一个具有非空密码的专用账号，并在服务电脑上完成一次身份验证；不要依赖“无密码共享”或映射盘符。映射盘符通常只属于创建它的登录会话，守护服务可能无法看见。

`[WinError 1326] 用户名或密码不正确` 通常不是扫描代码问题，而是服务电脑与共享服务器之间的 SMB 身份验证失败。依次检查：

1. 服务电脑当前 Windows 账号。
2. 共享目录的“共享权限”和“安全权限”是否都允许该账号。
3. 共享服务器是否禁用了来宾访问或要求用户名密码。
4. 是否存在连接到同一服务器、但使用了另一组账号的旧会话。

可在管理员终端查看当前 SMB 连接：

```powershell
Get-SmbConnection
```

只在明确知道影响范围时再清理或更换保存凭据，避免中断其他正在使用的共享连接。

## 4. OCR 性能、队列与自动隐藏

OCR 使用单个本地引擎和串行任务锁。这样做是为了规避原生推理并发导致的卡死、崩溃或接口失效。识别过程中 CPU 利用率可能呈短暂峰值而不是持续满载；首次识别还会承担模型下载和初始化成本。

- 默认使用 12 个 CPU 推理线程，最多可通过 `PHOTO_WEB_OCR_CPU_THREADS` 调整到 16。
- 不要同时运行多个 `start*.cmd` 窗口，也不要额外启动多个 Uvicorn（ASGI Python 服务进程）工作进程来并发 OCR。
- OCR 任务完成后，比例派生图与原图共用同一素材记录，因此文字、隐藏状态和搜索索引会同步。
- 识别到书名号内容的图片会被自动标记为隐藏，源文件不会被删除，任务结果会写明原因。

## 5. 服务守护与更新

`start.cmd` 和 `start-nas.cmd` 会通过守护脚本启动单个服务进程。服务异常退出时，守护脚本会按有限次数重试；健康检查可用于确认恢复状态。

更新服务的安全步骤：

1. 等待正在执行的扫描、OCR 或审查任务结束。
2. 备份服务电脑上的 `config.local.json`、`data` 与 `logs`；这些均不应复制到公开仓库。
3. 用新代码覆盖程序文件，不覆盖本地配置和运行数据。
4. 若前端源码有变化，重新构建 `frontend/dist`。
5. 重启服务，访问 `/api/health` 或首页确认版本和状态。
6. 以一张非敏感测试图片完成扫描、预览和 OCR 验收。

## 6. 问题对照

| 现象 | 优先检查 |
| --- | --- |
| 网站无法打开 | 服务窗口是否仍在运行；端口是否被其他程序占用；本机 `http://127.0.0.1:8000/api/health` 是否返回 `status: ok`。 |
| 局域网电脑打不开 | 服务电脑防火墙是否允许 TCP 8000；客户端是否使用服务电脑地址，而不是自己的 `127.0.0.1`。 |
| 扫描报 WinError 1326 | 按第 3 节用服务账号直接列出共享目录，确认 SMB 权限与身份验证。 |
| 提示 PaddleOCR 未安装 | 在实际启动服务的 Python 环境执行 OCR 安装命令，然后关闭旧窗口并重启。 |
| OCR 首张很慢或长时间无进度 | 检查服务终端是否正在下载模型、网络是否可用；等待初始化完成后再试单张图片。 |
| 批量 OCR 时其他操作变慢 | 减小批量，保留单个服务进程；不要用多实例绕过队列锁。 |
| 服务运行很久后离线 | 检查守护窗口、`logs` 与健康检查；确认没有手动关闭守护窗口或启动了相互竞争的实例。 |

## 7. 公开发布检查清单

发布前应确认仓库中没有：

- `config.local.json`、数据库、日志、发布包或素材文件；
- 真实服务器名、设备名、内网 IP 地址、共享路径、账号或密码；
- 个人姓名、客户名称、未授权图片、OCR 原文或内部阶段记录；
- 截图中的姓名、路径或可识别的敏感信息。

本仓库的配置模板和界面截图均采用占位符或已脱敏版本；每次新增文件后仍应重新检查。
