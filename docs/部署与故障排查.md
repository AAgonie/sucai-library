# 完整部署、OCR 与故障排查手册

本文适用于把“短剧广告大图素材库展示网站”部署到一台 Windows 服务电脑，再由局域网内的已授权电脑访问。示例中的 `FILE_SERVER`、`SERVICE_HOST` 和共享路径都是占位符，必须替换为实际环境信息；不要将真实路径、账号或密码写入公开仓库。

## 1. 部署架构与边界

- 服务电脑运行 Python 后端、前端静态文件、SQLite（轻量级文件数据库）和本地 OCR（Optical Character Recognition，光学字符识别）引擎。
- 浏览器客户端只访问 `http://SERVICE_HOST:8000`；所有客户端共用服务电脑的 `data` 数据库，因此扫描、OCR 与隐藏状态会同步。
- 图片仍保存在已授权的数据源中。服务电脑必须具有读取权限；使用多比例导出、回收站或删除功能时，还需要相应目录的写入权限。
- 推荐仅用于受信任局域网。项目没有面向公网的账号登录、HTTPS（Hypertext Transfer Protocol Secure，超文本传输安全协议）或权限隔离层，不应直接暴露到互联网。

## 2. 部署前准备

服务电脑需要：

1. Windows 10/11 或 Windows Server，建议使用稳定的固定 Windows 账号运行服务。
2. 64 位 Python 3.12。启动脚本直接调用 `python`，因此 `python --version` 必须显示 3.12.x，不能只保证 `py -3.12` 可用。
3. Node.js LTS（Long-Term Support，长期支持）版本；公开仓库不提交 `frontend/dist`，首次部署需要构建前端。
4. 能访问图片数据源的网络与 Windows 共享权限。
5. 建议给服务电脑分配固定局域网地址，方便客户端长期访问。

不要把项目放进网络共享目录、云盘同步目录或临时下载目录；选择一个本地、稳定且普通用户可写的文件夹即可。

## 3. 获取代码与检查环境

可在本仓库的 Releases 页面下载源码压缩包，或克隆仓库。解压/克隆后，以 PowerShell 打开项目根目录。

先确认解释器和 Node.js：

```powershell
python --version
node --version
npm --version
```

若 `python --version` 不是 3.12.x，请先安装 Python 3.12 并启用 “Add Python to PATH”，重新打开 PowerShell 后再继续。不要在一个 Python 版本安装依赖、用另一个 Python 版本启动服务。

## 4. 安装基础依赖与构建前端

在项目根目录依次执行：

```powershell
python -m pip install --upgrade pip
python -m pip install -r backend\requirements.txt

Set-Location frontend
npm ci
npm run build
Set-Location ..
```

构建成功后检查前端入口是否存在：

```powershell
Test-Path frontend\dist\index.html
```

结果应为 `True`。如果未构建前端，后端虽然可启动，但不会挂载网站首页。

## 5. 创建本机配置

复制模板，配置文件只保存在服务电脑：

```powershell
Copy-Item config.example.json config.local.json
notepad config.local.json
```

最常见的是 Windows SMB（Server Message Block，Windows 文件共享协议）共享目录。可按以下结构填写：

```json
{
  "nas": {
    "type": "smb",
    "host": "",
    "share": "",
    "base_path": "\\\\FILE_SERVER\\shared\\image-library",
    "username": "",
    "password": "",
    "recursive": false
  },
  "app": {
    "title": "短剧广告大图素材库展示网站",
    "default_batch_size": 50,
    "allowed_extensions": [".jpg", ".jpeg", ".png", ".webp"],
    "derivative_output_path": "\\\\FILE_SERVER\\shared\\image-library\\derived"
  }
}
```

说明：

- SMB 模式以 `base_path` 为准，格式是 UNC（Universal Naming Convention，Windows 网络路径）路径，例如 `\\FILE_SERVER\shared\image-library`。
- 当前 SMB 扫描使用启动服务的 Windows 账号访问共享目录；配置中的 `username` 和 `password` 用于 HTTP 数据源的 Basic Authentication（基础认证），不能替代 Windows 共享登录。
- 如果不使用派生图导出，可先保留通用 `derivative_output_path`；需要导出前必须改成实际可写目录。
- `recursive: false` 只扫描第一层；需要扫描子目录时改为 `true`，首次扫描量可能显著增加。
- `config.local.json`、`data` 和 `logs` 都不能提交到 GitHub。

在启动网站前，用同一台服务电脑、同一 Windows 账号测试共享权限：

```powershell
Get-ChildItem "\\FILE_SERVER\shared\image-library" -ErrorAction Stop | Select-Object -First 1
```

此命令失败时，网站连接测试和扫描也会失败。请先修复共享服务器的共享权限和 NTFS 安全权限，不要依赖某个交互登录会话里的映射盘符。

## 6. 安装本地 OCR

只需浏览、扫描和筛选时可以跳过本节；需要识别图片文字时，在**同一个 PowerShell、同一个 Python 3.12 环境**执行：

```powershell
python -m pip install paddlepaddle==3.2.0 -i https://www.paddlepaddle.org.cn/packages/stable/cpu/
python -m pip install -r backend\requirements-ocr.txt
```

安装完成后验证：

```powershell
python -c "import paddle; print(paddle.__version__)"
python -c "from paddleocr import PaddleOCR; print('PaddleOCR OK')"
```

两条命令均成功才表示 OCR 依赖已装入将被启动脚本使用的 Python 环境。首次识别会下载并初始化模型，耗时通常明显高于后续识别；模型缓存属于运行服务的 Windows 账号，换账号或换电脑后会重新建立缓存。

### OCR 性能设置

默认使用 PP-OCRv5 mobile 轻量模型和 12 个 CPU（Central Processing Unit，中央处理器）推理线程。可在启动前临时调整线程数，范围为 1 到 16：

```powershell
$env:PHOTO_WEB_OCR_CPU_THREADS = "12"
.\start-nas.cmd
```

需要尝试偏精度的 medium 模型时：

```powershell
$env:PHOTO_WEB_OCR_MODEL_PROFILE = "medium"
.\start-nas.cmd
```

OCR 在一个服务进程中串行执行，这是为了避免 PaddleOCR 原生并发推理造成卡死或服务失去响应。不要通过同时启动多个 `start*.cmd` 窗口或多个 Uvicorn 工作进程来提速。

## 7. 启动服务

### 仅本机使用

双击或在 PowerShell 执行：

```powershell
.\start.cmd
```

访问 `http://127.0.0.1:8000`。

### 提供给局域网使用

在服务电脑执行：

```powershell
.\start-nas.cmd
```

该模式监听所有网络接口的 TCP 8000 端口。服务电脑本机访问 `http://127.0.0.1:8000`；其他电脑访问 `http://SERVICE_HOST:8000`。

如果 Windows 防火墙拦截局域网访问，请以管理员身份运行 PowerShell，并仅在受信任网络环境创建入站规则：

```powershell
New-NetFirewallRule -DisplayName "短剧广告大图素材库 TCP 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
```

启动脚本会调用守护程序，以单个 Uvicorn 服务进程运行。服务异常退出时会依次等待 5、10、20、40、60 秒后重试；启动后 30 秒开始健康检查，连续 3 次失败会重启服务。守护日志位于 `logs\supervisor.log`。

## 8. 首次验收

按此顺序检查：

1. 在服务电脑打开首页，确认界面可加载。
2. 访问健康检查：

   ```powershell
   Invoke-RestMethod "http://127.0.0.1:8000/api/health"
   ```

   返回中应包含 `status: ok` 与版本号。
3. 进入“配置/扫描”，点击“连接测试”，确认共享目录可访问。
4. 先扫描小目录或少量图片，确认缩略图与筛选正常。
5. 已安装 OCR 时，选一张图片执行“识别文字”，等待任务完成后检查文字搜索。
6. 使用第二台电脑访问服务地址，确认能看到相同的入库记录和 OCR 结果。

OCR 识别到成对书名号（如 `《内容》`、`〈内容〉`）时，会自动隐藏该记录并报告原因。隐藏不会删除源文件；启用“显示隐藏图片”后可继续审查与恢复。

## 9. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `PaddleOCR 未安装` | 依赖安装到了错误的 Python。重新确认 `python --version` 为 3.12，再执行第 6 节命令并重启服务。 |
| 首张 OCR 很慢 | 通常是模型首次下载和初始化。确认服务终端没有报错，等待完成后再以第二张图片测试。 |
| CPU 没有持续满载 | OCR 存在读图、模型初始化和单任务串行阶段；短时峰值属于预期。不要用多服务并发绕过队列锁。 |
| 扫描报 `WinError 1326` | 服务电脑与共享服务器的 SMB 身份验证失败。用第 5 节命令验证服务账号，检查共享权限、安全权限和已有连接凭据。 |
| 服务电脑可打开，其他电脑打不开 | 确认使用的是服务电脑地址而非客户端自己的 `127.0.0.1`，并检查服务电脑 TCP 8000 防火墙规则。 |
| 网站只显示空白或 404 | 重新执行第 4 节的 `npm ci` 与 `npm run build`，确认 `frontend\dist\index.html` 存在，再重启服务。 |
| 长时间运行后服务离线 | 查看 `logs\supervisor.log`；不要关闭启动窗口。守护程序会自动重试，健康检查连续失败时会重启子进程。 |
| 多台电脑 OCR 结果不同 | 必须都访问同一个服务地址。若每台电脑各自启动服务，就会使用各自的 SQLite 数据库。 |

## 10. 更新与备份

更新前先等待扫描、OCR、重复审查等后台任务完成。然后备份服务电脑上的下列本地文件：

- `config.local.json`
- `data\`
- `logs\`

更新时只覆盖程序源码和构建产物，不覆盖以上本地文件。前端源码有变化时重新执行第 4 节的构建命令；更新完成后重启服务，并按第 8 节至少完成一次健康检查、扫描和单图 OCR 验收。

## 11. Docker 说明

仓库提供 Dockerfile，但默认镜像只安装基础后端依赖，不包括 PaddleOCR；Windows SMB 身份也不会自动传入容器。因此需要 SMB 扫描和本地 OCR 的场景，优先采用本文的 Windows 原生部署方式。若要使用 Docker，应先构建 `frontend/dist`，再自行解决容器的共享挂载、OCR 依赖和数据卷权限。
